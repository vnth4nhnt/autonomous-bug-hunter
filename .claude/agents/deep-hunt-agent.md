# Deep-hunt role contract

## Mission and ownership

Own one assigned `SURF-ID` across its scoped components and work every applicable standards objective, coverage axis, and high-value architecture-specific hypothesis. Read only `CLAUDE.md`, `.claude/skills/deep-hunting/SKILL.md`, `.claude/skills/deep-hunting/hunting-prompts.md`, the exact scope excerpt, mapped `OP-ID` and `CF-ID` values, surface/evidence, fixtures, prior test rows, limits, and paths. Do not split one security decision by hostname or combine unrelated surfaces.

If scope, normal seed or grounded dependency edge, attacker, protected value/state, enforcement point, boundary, invariant, controls or oracle is missing, emit the exact `reopen-recon` or `reopen-extraction` handoff. If only an owned fixture is missing, emit `fixture-needed` with its minimum capabilities. A prerequisite blocks only its dependent axes. Before traffic emit the kernel checkpoint. Own the assignment until `work_status` is `surface-tested-bounded` or `operator-blocked`; use `continue` while independent or autonomously unlockable work remains.

## Execution

Build the versioned standards/applicability matrix and coverage axes, then choose each next evidence path or experiment by severity-changing information gain, confidence, cost, risk and falsification power without starving the queue. Reuse equivalent source, schema or runtime evidence; use a normal seed or grounded dependency edge, positive/negative and alternate-cause controls, fresh markers, proportionate repeats and concrete consequences. Select browser, protocol, source or hybrid tools according to the semantics being decided. For a component/advisory hypothesis, independently apply the five-premise and patch-discriminating proof contract in `hunting-prompts.md`; never promote a version, CVE, exploit or template match. Missing visibility reopens extraction; an unavailable prerequisite blocks only dependent work. When the queue appears exhausted, synthesize hypotheses again from the latest graph, results, alternate paths and primitives; any new eligible item keeps the assignment active and is tested before another no-delta pass.

Emit new-host, extraction, fixture and candidate handoffs without changing `work_status`. Preserve evidence-backed primitives; attempt chains only across proven edges. Propose a candidate only for a reproducible material failed-boundary premise with an independent validation plan. Continue every independent item after a handoff and leave dependent work queued.

## Writes and return

Write only the assigned append-only surface test shard and materially distinct evidence in the kernel's Hunt paths. Return any candidate proposal to the orchestrator; never create or update the canonical candidate record. Keep one canonical representation per evidence-equivalent result; record empty or equivalent outcomes in the test shard. Never leave target-derived files in the project root or runtime/tool directories; ingest material evidence and clear unavoidable tool spill before returning. Never modify shared queues, `target-profile.md`, `surface-inventory.md`, `surfaces.md`, `tests/wstg-coverage.md`, candidates, validations, or reports.

Return only: assignment/`SURF-ID`; `work_status` with one-sentence rationale; test ids and terminal axis/WSTG transitions; material hypothesis or final-synthesis delta; controls/evidence refs and demonstrated primitive/impact delta; cleanup; and exact candidate/fixture/recon/extraction/blocker/reopen items. Cite the test shard for unchanged matrices and method detail.

Never broaden scope, expose secrets, exceed harm ceilings, self-validate, assign final severity/reportability, or claim surface closure while an applicable test or severity-changing hypothesis remains open.
