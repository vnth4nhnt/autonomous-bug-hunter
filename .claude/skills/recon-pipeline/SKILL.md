# Recon pipeline

## Owner and boundary

The orchestrator may run this method inline or assign one scoped host, one non-overlapping bounded host batch, or one passive discovery population to `recon-agent`. A batch names one `BATCH-ID` and every exact SCOPE/HOST member id; it is an execution envelope, not a queue item or aggregate verdict. A delegated agent writes only materially distinct redacted evidence and proposes deltas; the orchestrator alone updates the host/surface queues and `target-profile.md`.

Recon discovers and verifies breadth. It does not perform authenticated role/state extraction, broad vulnerability fuzzing, candidate validation, or safety claims.

Treat only a scope-matched host/service with a real HTTP or relevant protocol response as live. Passive, DNS/TLS-only and non-responding candidates receive reachability verification and final refresh only; never assign them the sensitive baseline, extraction or hunting until a real response promotes them.

The host baseline and its completion evidence are invariant. Within that boundary, choose passive sources, protocol clients, browser capture, public implementation metadata or a hybrid by expected routing value and cost. Do not repeat equivalent discovery merely because a named tool is available.

Resolve `engagements/<name>/knowledge-base/artifacts/recon/` before the first command and use only verified descendant paths for target-specific work. Project-owned locked inputs remain at their canonical project paths and are never copied into this directory. Retain normalized reproduction inputs and every materially distinct result needed for classification or routing, with one canonical representation per evidence-equivalent result; record empty/equivalent outcomes in the recon record instead of keeping zero-byte logs or duplicate stdout/structured output. Never use the project root as a working/output directory. Ingest unavoidable Playwright spill, retain its materially distinct evidence and clear the rest after each batch.

Do not create executable helpers in `.runtime/`; it is installer-owned. Keep one-off transformations as attached inline commands. A committed helper is justified only for generic deterministic mechanics repeated across engagements and may not choose scope or tests, own/reconcile queues, schedule target batches, impose a wall-clock batch deadline, interpret evidence or emit a security/coverage verdict.

## Continuous queue loop

1. Read original scope, carve-outs and the active assignment. Expand subdomains only for an explicitly assigned wildcard; an exact host assignment never expands.
2. For an assigned wildcard, run passive discovery, preserve provenance and scope-match each result before traffic. Stream scope-matched candidates into attached reachability waves as they appear; never wait for the full discovery population to finish before starting `httpx`. Repeat discovery incrementally after new relationships and once when the other queues appear drained.
3. Verify reachability immediately in the attached pool before assigning the full baseline. A node becomes a verified web host only after a real HTTP response; DNS, TLS metadata or a passive name alone is insufficient. Record bounded no-response as `unreachable-at-time` with transport cause, observation window and final-refresh trigger. Retry it at most once only when target evidence supports a transient or alternate scheme/SNI cause; never serialize long retries across the unresolved population. For each verified host/service, calibrate individually and fill the attached baseline pool within the per-host, shared-failure-domain and global limits in `CLAUDE.md`. Split hosts that differ in DNS/TLS, application behavior, identity realm, consumer/provider role, or technology; a shared template never proves shared security behavior.
4. Record host/service and relationship deltas, then route every value-bearing application or unresolved trust edge to `attack-surface-extraction`. This includes identity/SSO, payment, email, signed capability, storage/CDN, webhook, worker/queue, cross-origin message, and third-party callback edges; an external consumer or redirect does not erase the in-scope producer, relying party, callback, session, or enforcement decision.
5. Reconcile each completed bounded wave before reusing its capacity or issuing successor work for its members; unrelated attached waves may continue. Commit a returned disposition for every assigned member, including unchanged/no-delta members, and route each live member to extraction immediately rather than waiting for the wildcard population to finish. Keep downstream capacity under the kernel backpressure rule. Continue until the current host queue is drained. `defer` changes priority but remains queued and cannot satisfy closure.

## Per-host web baseline

For every verified scoped web host:

1. Resolve DNS, inspect certificate/SAN and redirect behavior, then verify HTTP with a real fetch. Preserve scheme, port, status, title, technology/build hints, final location, representative body signature, wildcard/soft-404 behavior, ownership contradictions and any credible official source/schema provenance without claiming a deployment match. No response, refusal, DNS failure or TLS failure is a terminal reachability observation for that attempt, not an operator blocker; recheck it in the final incremental refresh but do not assign the sensitive baseline until a web response is observed.
2. Before the wordlist, calibrate the host with the root or observed valid path, at least two impossible paths, and three to five high-signal sentinels selected from `robots.txt`, `sitemap.xml`, `.git/HEAD`, `.env`, and one technology-derived path. Compare status, redirect destination, content type, size, stable body structure, and title. Record any path-independent external redirect, wildcard, WAF, or empty-router response as a noise fingerprint, not as permission to skip the baseline. Do not follow an external redirect.
3. Obtain one representative normal entry with the least costly semantics-preserving client. For a browser application, headless Playwright normally captures redirect/identity realm, first-party origins, initial network exchanges, forms, HTML/script/import-map/manifest references, workers/service workers and obvious API/storage/CDN relationships. If this grounds a normal public self-registration flow permitted by program rules, return its route/form/action/API evidence immediately as `eager_fixture: create-minimum-account` on the `extract` handoff; the orchestrator creates the exact FIXTURE item and runs `identity-signup` inline while independent recon continues. Recon does not own credentials or perform authenticated walking. For API/message services, capture the real protocol and schema/documentation roots instead of manufacturing browser work. For a uniform external redirect, record the trust edge without treating the destination as a probe target. Authenticated route, feature and lazy-asset walking belongs to extraction.
4. Run one non-recursive, normally unauthenticated, GET-only sensitive-resource baseline on every currently responding verified scoped web host unless an exact scope or protocol exclusion applies. If the normal control ceases responding, return the host to reachability classification instead of inventing an instability blocker. Resolve `wordlists.sensitive-baseline.file` from project-root `tools.lock.json`; its canonical locked file is `.claude/skills/recon-pipeline/assets/sensitive-baseline.txt`, the pinned 343-entry high-signal relative-path profile curated from Bo0oM `fuzz.txt`. Pass that resolved project file directly to `ffuf`; never copy, rename or alias it inside the engagement and never load it into model context. It covers only consequential VCS metadata, secrets/configuration, backups/archives/databases, logs/debug/management surfaces, cloud/CI/deployment material, framework secret files and a few proven high-value normalization/case variants. It is ordinal-unique and contains no leading slash, query string, traversal, request body, or state-changing method. Keep all raw JSON matches, then group them by status, redirect destination, content type, size, words, and lines against the calibration fingerprints; do not prefilter away same-size redirects or other possible exceptions. Do not attach session cookies or follow redirects off the scoped host. Add only technology- or evidence-derived paths and backup forms such as an observed filename plus `.bak`, `.old`, `~`, `.zip`, or `.map`; never build a Cartesian wordlist. Public discovery paths and broad content names do not belong in this baseline. Inspect only the minimum response needed to classify exposure and redact secrets immediately.
5. A security-relevant `401` or `403` is a follow-up signal, not absence. First distinguish application authorization from authentication failure, WAF/gateway denial, soft-404 behavior, and a nonexistent resource. Only when existence or relevance is grounded by a link/code reference, positive sibling, distinctive denial, or other target evidence, run at most eight one-axis variants selected from: segment or extension case; one percent-encoded dot or separator at the suspected proxy/application boundary; one redundant separator, dot segment, or trailing path form; or an observed equivalent method, route, API version, or rewrite header. Do not generate casing powersets, recursively encode, spray trusted headers, or apply variants to every wordlist entry. A differential response reopens extraction or the applicable WSTG authorization/parser test; it is not a finding by itself.
6. For each server-side script filename actually observed in HTML, JavaScript, errors, manifests, source maps, or normal traffic, test at most two mixed-case extension variants when a handler, proxy, CDN, or filesystem case boundary is plausible (for example `.php` versus `.pHp`). Compare against the normal script and an impossible sibling. Treat raw source, a changed content type, or handler bypass as a candidate signal requiring controlled validation; never enumerate case permutations over guessed filenames.
7. Record every credible evidence root for extraction: runtime flows, first-party code/manifests/maps, schemas, official or recovered source, SDK/mobile artifacts, documentation and external trust edges. Assign only preliminary source-to-deployment confidence; extraction reconciles it. Do not claim coverage from a landing page, banner or upstream repository alone.

If direct checks confirm exposed `.git`, use `git-dumper` only on that scoped path and retain the minimum evidence necessary. Never start it from a status code or guessed technology alone.

## Tool routing

The commands below are verified defaults and output contracts, not a requirement to use a weaker source when a semantics-preserving equivalent is already available. Every artifact placeholder is the full final path including the stated extension, resolved beneath the engagement before dispatch. After return, cite only that exact path if the file exists; never infer an alias or change `.jsonl` to `.json`. The pinned `ffuf` baseline remains required because its exact input set is a coverage invariant.

- Use `subfinder -d <suffix> -silent -o <artifact.txt>` only when an explicit wildcard authorizes matching subdomains. Scope-match its output before traffic; never run it for an exact hostname.
- Feed each scope-matched candidate wave directly to `httpx -l <scoped-input> -t 50 -json -sc -title -td -location -o <artifact.jsonl>` while passive discovery continues. Do not add a global rate limit unless program rules or observed instability require one.
- Use `naabu` only when the scope explicitly authorizes port discovery. Prefer named or small port sets, save JSON, and verify material results with the real protocol.
- Use headless `playwright` for representative browser behavior and network/JavaScript roots. Do not use `playwright-headed` during ordinary recon.
- Use `ffuf` after calibrating each verified host with the resolved project-owned sensitive baseline plus evidence-derived sensitive paths: put the relative-path word at `https://<scoped-host>/FUZZ`, no recursion, `-mc all -t 10 -rate 25 -timeout <seconds> -s -of json -o <artifact.json>`, no response prefilter and no redirect following. Set a finite per-request transport timeout from observed normal latency (20 seconds by default; increase only when valid controls show the application normally needs longer). Let the finite exact input finish naturally; never set `-maxtime`, `-maxtime-job` or a scheduler/batch deadline. Fill an attached pool of up to eight calibrated hosts while keeping <=10 workers and <=25 requests/second per host, <=80 workers and <=200 requests/second globally, and <=100 requests/second per apparent shared failure domain. Reallocate unused workers when latency requires it without exceeding those caps. Reduce concurrency or stop affected jobs together on 429, WAF bursts, rising latency/errors, or instability. Uniform routing is a classification target, not an early-stop condition. Every job must remain owned, observable and cancellable; do not detach a fleet scheduler.

  Exact-input completion means every pinned input was dispatched once and reached a terminal response or recorded transport outcome. A transport failure counts as attempted and must not be retried merely because ffuf JSON contains no match row for it. With `-mc all`, after natural completion record the exact dispatched-input minus JSON-result set as transport-no-response, not as undispatched. Prove dispatch with the exact input digest/count plus natural completion of that input or deterministic disjoint shards; JSON is response evidence, not the dispatch ledger. If a job is externally interrupted before dispatch completion, replay only its smallest known incomplete shard; when the boundary is unknown, replay that shard, not the entire host population. Retry once only for an identified transient/tool cause and change the relevant factor; otherwise pivot to an equivalent attached client or retain the observed transport outcome. An equivalent client must preserve the locked input digest/order, calibrated request semantics, redirect/cookie behavior, attached rate/concurrency and the response/body fingerprints needed for the same noise classification; a header-only sweep is not equivalent. Preserve meaningful `401/403` results for the bounded follow-up above. Do not use `sqlmap` or `interactsh-client` for generic recon.

For every run record normalized inputs, exact command/MCP action, version, rate/concurrency, timestamps, exit, failures and calibration; retain materially distinct redacted outputs and remove evidence-equivalent copies. Empty output is recorded as bounded to that input, method and time, not retained as an empty file.

## Status, handoff, and output

Keep completion separate from routing:

- `work_status`: `continue` while recon work remains; `recon-bounded` when the assigned pass is complete for its observation window, including a scoped candidate recorded `unreachable-at-time` and rechecked at final refresh; `out-of-scope` only when evidence excludes the node; or `operator-blocked` only for an exact operator-only prerequisite. Transport failure and elapsed batch budget are never `operator-blocked`;
- `handoff`: `extract` for a verified in-scope web application or unresolved value edge; use `none` only with an explicit evidence-backed rationale that no security-relevant local decision or value transfer was observed;
- `eager_fixture`: `create-minimum-account` with the grounded registration evidence and target graph requester, or `none`; it is separate from `work_status` and never waits for recon completion when present;
- `candidate-scope` nodes remain separate no-traffic queue items until ownership and a matching scope rule are resolved;
- `defer` is only a scheduler priority flag with a revisit trigger and never a terminal work status.

When inline, update `target-profile.md` and queues. When delegated for one host, return that member's status and routing. For a batch, return `BATCH-ID`, envelope state and exactly one compact result for every assigned member: `item id | node | live/non-live/out-of-scope classification | baseline state or exclusion | work_status | handoff | eager fixture trigger | evidence/reason | next action/reopen`. Absence of a material delta never permits omission. A large batch may put this exact table in one cited normalized recon artifact and return its count/digest plus exceptions, but the orchestrator must read and commit every row before marking the envelope reconciled. Emit a newly grounded eager fixture trigger as an immediate delta rather than waiting for the rest of the batch. Then return only material relationship/baseline/evidence-root deltas, contradictions and exact candidate-scope/defer/blocker/reopen items.

The recon queue is ready for active-boundary closure only when every original wildcard population and scoped host/service is `recon-bounded` or evidence-backed `out-of-scope`, every currently responding verified web host has the exact-input baseline or an exact scope/protocol exclusion, every non-responding candidate has a bounded reachability observation plus final-refresh result, every value-bearing relationship has `extract` routing or an evidenced non-security rationale, every application with observed permitted public self-registration has an emitted eager fixture trigger while alternate flows may map to the same reusable fixture request, no operator-blocked item, testable `defer` or unresolved `candidate-scope` remains, a final in-scope refresh yields no new scoped node, relationship, sensitive resource or evidence root, and no target-derived artifact or spill remains outside the active engagement evidence root.
